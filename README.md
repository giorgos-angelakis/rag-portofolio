# 📄 AI Document Chat — Production-Ready RAG Web App & API

A high-performance, lightweight **Retrieval-Augmented Generation (RAG)** application built with Python, FastAPI, LangChain (LCEL), FastEmbed, FAISS, Groq, and Streamlit.

This service allows users to dynamically upload PDF documents, generate vector embeddings on the fly, and perform intelligent, context-aware querying using Llama 3.3 70B.

## 🌐 Live Interactive Demo & How to Use

🚀 **[Click Here to Open the Live Web Application](https://bestragai.streamlit.app)**

### 📖 How to Use the App
1. **Open the App**: Click the link above to open the Streamlit interface in your browser.
2. **Verify Backend URL**: Check the sidebar to ensure the **FastAPI Backend URL** points to the live Render endpoint (`https://your-app-name.onrender.com`).
3. **Upload a PDF**: Use the sidebar file uploader to select a PDF document (e.g., short research paper, resume, or report).
4. **Process Document**: Click **Process PDF**. The backend will extract text chunks and generate embeddings in memory.
5. **Ask Questions**: Type your questions in the chat box to retrieve accurate, context-aware answers generated by Llama 3.3 70B.

> *Note: Hosted on Render's free tier. If the backend has been idle for 15+ minutes, the initial file upload may take ~30–45 seconds while the server wakes up.*

## 🌟 Key Features

* **Dynamic PDF Ingestion**: Upload custom PDF documents directly from the UI to create real-time vector indexes.
* **Memory-Optimized Embeddings**: Powered by `FastEmbed` (ONNX Runtime) instead of heavy PyTorch runtimes, keeping total memory consumption under **150MB RAM** for free-tier cloud deployment.
* **Ultra-Fast Inferences**: Answers generated via Groq's high-speed Llama 3.3 70B inference engine.
* **Modern LCEL Pipeline**: Built using LangChain Expression Language (LCEL) for robust, future-proof RAG chains.
* **Decoupled Architecture**: Features a standalone FastAPI REST backend paired with an interactive Streamlit frontend.
* **Containerized & Cloud Ready**: Packaged with Docker and deployed on cloud infrastructure (Render + Streamlit Community Cloud).

## 🏁 Quickstart (Local Development)

### 1. Prerequisites
* Python 3.10 or higher
* A free Groq API key from [console.groq.com](https://console.groq.com)

### 2. Clone Repository & Setup Virtual Environment
```bash
git clone https://github.com/your-username/rag-portfolio.git
cd rag-portfolio

# Create virtual environment
python -m venv venv

# Activate virtual environment
# Mac/Linux:
source venv/bin/activate
# Windows:
venv\Scripts\activate
```

### 3. Install Dependencies
```bash
pip install -r requirements.txt
```

### 4. Environment Configuration
Create a `.env` file in the root directory and add your Groq API key:
```env
GROQ_API_KEY=your_actual_groq_api_key_here
```

### 5. Launch Local Servers

**Terminal 1 — FastAPI Backend:**
```bash
uvicorn main:app --reload
```
*The API interactive documentation will be available at `http://127.0.0.1:8000/docs`.*

**Terminal 2 — Streamlit Frontend:**
```bash
streamlit run app.py
```
*The Web UI will automatically open at `http://localhost:8501`.*

## ⚠️ Current System Limitations

This project was intentionally designed as a lightweight, low-cost proof-of-concept (MVP) to fit strictly within free-tier cloud constraints (512MB RAM cap). As a result, it has the following operational limitations:

1. **Single-User Concurrency (1 Person at a Time)**:
   * The vector store is maintained as a single global state in server memory. If a new user uploads a PDF, it overwrites any previously active document session.
2. **Document Size & Page Limits**:
   * Designed for small-to-medium documents (**1 to 20 pages**, file size **<10 MB**). Uploading large books or 500+ page PDFs will exceed the 512MB RAM limit and cause HTTP gateway timeouts.
3. **Ephemeral Vector Storage**:
   * Vector indexes exist in temporary container memory. When the cloud server goes to sleep due to inactivity, the uploaded document session is cleared.

---

## 💡 Key Architectural Changes for Production Scaling

To scale this application for enterprise multi-tenant workloads with 500+ page documents, the following architectural enhancements would be implemented:

1. **Async Task Queues (Celery + Redis)**:
   * Offload PDF parsing and chunk embedding generation to background worker processes, preventing HTTP gateway timeouts during large file processing.
2. **Managed Cloud Vector Database (Pinecone / Qdrant / Supabase pgvector)**:
   * Move vector storage out of local Python memory to a dedicated cloud database with persistent indexing and disk-backed storage.
3. **Session-Based Isolation (Multi-Tenancy)**:
   * Attach unique `session_id` identifiers to vector embeddings during ingestion, enabling multiple users to upload and chat with different documents concurrently without data collision.
